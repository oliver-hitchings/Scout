# Local OpenAI-compatible provider

- Added direct local-model HTTP execution for scans, evidence-bound setup proposals, fit assessments and text chat, without any Codex/Claude CLI dependency.
- Added endpoint/model/API-key-file settings and exact namespaced model identifiers throughout queue, recovery and assessment provenance.
- Structured output receives JSON-schema validation in Scout; one explicit capability rejection permits a strict-JSON fallback with the same validation.
- Added total request deadlines, bounded transient retries, redirect refusal, sanitised failures and structured model health probes. Configuration presence alone remains unverified.
- Local authentication and network failures create durable provider warnings, deduplicated by episode and replayed safely after deferred outbox publication.
- Added synthetic HTTP boundary tests for success, schema fallback, malformed/invalid output, authentication, rate limits, transient server failures, deadlines, redirects and production scan/chat wiring.
- Existing workspaces retain their provider choice. Local models are opt-in; key contents remain outside configuration, journals and diagnostics.
- Release staging recognises only the reviewed bytes of Ajv's public schema-security metadata while retaining every credential and personal-marker check. Browser acceptance covers the third engine card, unchanged empty-local settings requests and the complete offline module graph.
