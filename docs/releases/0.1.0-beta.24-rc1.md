# Scout 0.1.0-beta.24-rc1

This release candidate prepares the standalone desktop and always-on household
work for final review. Its package, lockfile, installer, artifact names and signed
metadata use the same candidate version. It is not evidence that a release has
been published or installed successfully on every platform.

## Desktop and household improvements

- Choose quiet background watch or active hunting, with consistent score
  thresholds, durable match/provider alerts and explicit recovery actions.
- Use a local OpenAI-compatible model through an approved endpoint, alongside
  Codex and Claude. Local model transport settings require host access; key files
  stay within approved private secret directories. Public endpoints require
  HTTPS, and settings explain when CV/job text or credentials leave the host.
- Review and approve Living CV changes, preserve immutable versions, and prepare
  editable CV or cover-letter drafts for explicit reviewed save. Applications
  and outreach remain human-reviewed drafts.
- Keep settings edits, expanded job cards, feedback and pointer actions through
  background refreshes. Fresh onboarding retains the profile-publication review
  needed before its first ranked scan.
- Run separate household workspaces, provider homes, ports and timers. A moved
  sibling instance is reported unavailable without stopping healthy instances;
  external CV sources cannot cross into another registered person's workspace.
- Review headless storage cleanup before applying it. Cleanup keeps the existing
  lease, recovery, content-digest and verified encrypted-archive protections.
  Summary and notification projections surface storage pressure.
- Recover delivery and household locks after proven-dead processes while
  protecting live owners. Command notifications require protected executable
  paths and Windows ACLs; Windows tray failures retain bounded local reason
  codes. Outbound notification hooks remain **off by default**.

## Upgrade and release safety

Existing explicit locale, currency, timezone and source-country choices remain
unchanged. Only missing values receive the neutral defaults `en`, `USD`, `UTC`
and no implicit Adzuna country; review these settings after an upgrade.

Native packaging binds the sealed payload to inspected content and filesystem
identities, then publishes through private temporary paths with no overwrite.
Tampering, output collisions, stale authorization and untrusted signatures fail
closed. The [release process](../RELEASE.md) and
[package-verification guide](../SUPPLY_CHAIN_SECURITY.md) describe these gates.

Production release-key enrollment remains an owner action. The bundled trust
registry is intentionally empty until enrollment, so installed apps refuse
updates without a trusted signature. Temporary test keys prove the signing chain
without enrolling production trust. Candidate tags keep artifact uploads,
deployment and publication disabled; preparing this version creates no tag.

## Required final acceptance

The [integration gate](https://github.com/oliver-hitchings/Scout/pull/85) records
the exact reviewed commit and evidence. Promotion still requires all four OS
test/audit jobs, twelve browser jobs, Windows native checks, all four installed
artifact checks, a strict privacy audit and a fresh independent review on that
integration head. Earlier passing branches do not replace these checks.

Live provider-auth acceptance, private-host systemd isolation, encrypted backup
and restore rehearsal, owner-marker clearance, protected release rehearsal and
production key enrollment remain separate operator gates. No live provider
login, private-host deployment, tag or publication is performed by preparing this
candidate. See [provider acceptance](../ACCEPTANCE.md),
[home-server operation](../HOME_SERVER.md) and [upgrades](../UPGRADES.md).
