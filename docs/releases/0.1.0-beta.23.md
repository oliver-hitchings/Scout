# Scout 0.1.0-beta.23

Jobs, speculative opportunities and shortlist refreshes retain open cards and
unfinished feedback while updating changed job facts. Keyboard focus and typed
explanations remain with the editor when its job stays in the list.

Provider recovery now has an automated acceptance command,
`npm run test:acceptance`, using real subprocesses and HTTP routes with synthetic
Claude/Codex executables. The packaged [acceptance guide](../ACCEPTANCE.md) also
sets out the owner's separate current-provider account check.

Failed chat and fit-assessment resends now reserve their one-use action on disk
before running. Disk errors block a resend safely and cannot make a completed
request execute twice.

This candidate advances Scout from beta.22. Beta 23 makes scans recoverable,
adds guided provider sign-in and health
recovery, improves Scout's character animation, and makes AI conversation
setup more reliable when provider information arrives asynchronously or a
desktop integration is unavailable.

## Provider recovery and saved messages

- Provider cards, sign-in guidance and diagnostic readiness now use the same
  health evidence. A remote sign-in failure survives local status checks and
  sign-in progress until a real remote check succeeds.
- Chat, fit assessment and setup proposals use the same provider preflight.
  Provider-work exclusion remains held until settled health evidence is saved.
- A failed sign-in keeps the chat request and offers **Resend with Codex** or
  **Resend with Claude** after reconnecting. Resending requires a click, preserves
  one copy of the user's message, and rejects a completed resend's replay.
- Local HTTP authentication failures offer **Resend with Local model** with
  guidance to check the model server and API-key file. Saved local conversations
  reopen with their provider selected, ready for the next message. Recovery
  never resends a message automatically, and the same one-use action applies.
- Routine checking and login progress no longer create failure alerts. A chat
  transcript save failure uses fixed public text without filesystem diagnostics.
## Search modes and local alerts

- Each workspace can choose quiet background watch or active job hunting during
  setup and later in Settings. The existing ranking/assessment gates now apply
  each mode’s match bar and per-scan cap.
- Exceptional assessed matches, daily active-hunt digests and provider failures
  enter a durable local outbox. Windows tray delivery and dashboard
  acknowledgement are deduplicated and separate. Outbound notifications are
  disabled by default; only an explicitly enabled owner-configured headless
  hook can send them. See [Search modes and alerts](../SEARCH_MODES_AND_ALERTS.md)
  for limits and the optional-hook guide.
- Switching to background watch durably clears unsent ordinary active matches
  and converts outstanding exceptional matches to a single alert. Returning
  to active hunting does not repeat them in a digest, and polling preserves
  the scan's recovery receipt.

## Ranked, profile-driven discovery

- Rechecking an unchanged advert with a full description preserves its identity
  and reports an unchanged keeper; genuine responsibility changes still require
  review. Existing digested advert evidence remains compatible.
- Adzuna's country is visible in setup and Sources settings. Salary currencies
  come from the queried country; unknown currencies stay unknown, and a minimum
  in another currency is not sent as a source filter.
- Duplicate grouping and durable identity reconciliation compare indexed
  candidate groups while preserving the complete matching rules and stable IDs.
- Generated onboarding content follows the workspace locale. Small plural
  result pools try soft diversity before recording any necessary relaxation.
- History readers accept both underscore and hyphen rejection outcomes and
  retain reassessment versions beyond the recent mixed-history window.

- Setup presents universal structured search questions before at most six
  specialist follow-ups. Selected answers update only the complete reviewable
  draft; publishing and hard exclusions retain their explicit confirmation
  boundaries.
- Publishing creates bounded, traceable search lanes for approved titles,
  locations, industries, skills, working patterns and employers. Exact
  duplicates merge, overlapping lanes remain visible, and fair rotation stops
  stored order from starving a lower-priority lane.
- Fresh onboarding now resumes at the complete search-profile review after
  proposal activation or a reload. The first scan remains disabled until that
  draft is explicitly published and never starts merely because setup answers
  were saved.
- Every selected lane records exact query returns, parsed records, unseen and
  eligible vacancies, detailed-assessment selection and promising outcomes in
  the same recoverable mutation as scan results.
- Lane review now shows returned, parsed, new, eligible, selected and promising
  evidence together with the exact profile rule value, strength and provenance
  used for the query before reversible retirement.
- Three completed non-failed unproductive runs make a lane eligible for
  explicit retirement in Settings. Retired lanes can be restored without
  losing history; removed profile rules are archived instead.
- Every successfully normalised unique vacancy is filtered and ranked before
  the detailed-assessment cutoff, so source, portal and lane order cannot
  starve a stronger later result.
- Interpretable title, responsibility, skill, qualification, industry,
  location, working-pattern, compensation, seniority, employer, freshness and
  novelty dimensions retain rule IDs, confidence and contribution evidence.
  The persisted per-vacancy explanation keeps the strongest contributions with
  their score, dimension and a one-line evidence note, so a report can say why a
  vacancy ranked high.
- Confirmed mandatory rules use an explicit support matrix across every
  published structured domain. Known contradictions exclude traceably, unknown
  facts follow the published policy, and unconfirmed inferences remain
  non-blocking. Canonical duplicates conservatively retain bounded,
  source-traceable hard-exclusion evidence from every trustworthy observation.
- URL-less vacancies derive deterministic coarse semantic IDs that remain
  stable as provider coverage and optional metadata change. Complete provider
  references disambiguate same-scan collisions and distinguish separate
  openings during lifecycle and novelty matching. Cross-source copies reconcile
  through shared semantic and reference evidence, and durable assessed plus
  pre-assessment decisions count as seen for novelty and lane-productivity
  accounting. Each vacancy explanation records its lifecycle change and reason
  (new, reopened, material change, profile or learning change, unchanged
  rejection), and a learning-version change now re-ranks an unchanged rejection
  without assessing it again. Unchanged rejected adverts stay remembered from the whole
  run log, so newer assessments no longer push them back into detailed assessment.
  Scans record their assessment prompt, schema, provider and model, and a change
  re-assesses earlier rejections at most six per scan, strongest first.
  Scan compatibility binds the
  selected lane-plan revision, lane IDs and query fingerprints so retirement
  or restoration cannot race stale work.
- Published compensation and location unknown-value policies now distinguish
  **include**, **penalise** and **exclude**. Unknown location facts can use
  **include**, **penalise** or **exclude** and are never silently treated as a
  positive match.
- Selection applies deterministic soft diversity across employers, sources,
  lanes, role families and locations without padding the assessment budget
  with weak or zero-score work.
- Coverage funnels reconcile returned, parsed, normalised, duplicate, unique,
  excluded, eligible, ranked, selected, assessed, failed and outcome counts,
  with bounded per-vacancy explanations.

## Employer registry and careers monitoring

- Publishing named-employer preferences reconciles a private, versioned
  `data/employers.json` registry without overwriting explicit decisions,
  access policy or history. Selected canonical adverts from any configured
  source add reviewable employer evidence at normal priority.
- Priority employers are selected whenever rate-eligible; relevant and normal
  employers rotate fairly; inactive employers receive infrequent validation;
  irrelevant employers remain excluded until explicitly restored.
- Greenhouse, Lever and Ashby public boards share a bounded monitoring
  contract. Reviewed careers pages prefer validated `JobPosting` JSON-LD;
  conservative same-site generic links are explicitly opt-in.
- Terms, robots, authentication, external redirects, anti-bot responses, rate
  limits and JavaScript-only pages fail safely with bounded health evidence.
  Raw pages and exception messages are not persisted.
- Employer selection is frozen at scan collection. Health, cadence and
  advert-discovery evidence are committed in the same fenced recoverable
  mutation as tracker, report, scan log and search-lane history.
- Settings exposes bounded origins, priorities, monitoring policy, health and
  recent outcomes with revision checks and explicit confirmation. Legacy ATS
  portals migrate into the registry and are never fetched as a duplicate
  source.
- Reviewed aliases, industries and locations can be added, removed and undone
  under an explicit revision-bound confirmation. Ambiguous aliases are rejected
  and monitoring executes one reconciled employer identity.
- Careers, advert and later liveness fetches are protected against server-side
  request forgery (SSRF): credentials and non-public IPv4/IPv6 destinations are
  rejected, every DNS answer is checked and pinned for the request, and every
  bounded redirect is revalidated. Structured `JobPosting` records require the
  bounded fields Scout uses, and expired `validThrough` evidence is not current.

## Recoverable scans

- Warm journal appends verify a bounded tail and private file identity instead
  of re-reading the complete history each time. Unexpected changes and
  interrupted writes force full validation; recovery, hash-chain checks,
  idempotency and fenced ownership remain in place.
- Scan progress is journalled before work begins, so interrupted work can be
  resumed or presented for review without silently repeating completed stages.
- Overlapping manual and scheduled requests are queued with bounded expiry,
  deduplication and visible status instead of racing the active scan.
- The dashboard shows `recovered` and `retrying` scan states distinctly, so an
  unattended recovery or per-job assessment retry is visible at a glance.
- Tracker, report and scan-log updates remain fenced, idempotent and
  recoverable across partial writes.
- Profile publication prepares one versioned multi-file intent and reconciles
  per-target receipts after interruption. Current-state beta.22 rollback
  snapshots are reused only when every protected live digest still agrees.
- Startup, periodic, UI and scan-owned backup checkpoints use the shared fenced
  lease and mutation coordinator. Busy work reports pending, lease loss never
  retries unfenced, and the existing successful, pending and partial scan
  outcomes remain distinct.
- Mutation guards record process-start and child-operation identities before
  Git spawn. An orphaned Git child blocks a successor until it is proven closed;
  bounded timeout kills its process tree and observes closure before release.
- A torn final queue append is quarantined with bounded content-addressed
  evidence while the valid prefix remains authoritative. Syntactically complete
  invalid queue records still fail closed, and retention preserves the receipt.
- Storage pressure produces warnings and eventually refuses unsafe new scan
  starts while preserving recovery-critical records.

## Provider health and sign-in

- Scout keeps a bounded, device-local health state for each configured
  provider and blocks scans truthfully when sign-in, a CLI update, the network
  or provider availability needs attention.
- Settings offers guided Codex and Claude sign-in with explicit retry and
  cancellation. A fixed manual command and official guide remain available
  when the guided flow cannot complete.
- A remote authentication failure continues to offer reauthentication even
  when the local CLI still reports that credentials are present.
- A persistent dashboard notice names a provider whose session has expired and
  the scheduled scans waiting on it. **Remind me later** acknowledges the alert,
  and once the provider is reconnected **Run missed scan now** and **Retry now**
  start the blocked scan through the normal scan entry points. See
  [reconnecting a provider](../RECONNECT_PROVIDER.md).
- Guided sign-in, verification and credential clearing fence new chat and
  onboarding work for the same provider only. Other providers remain usable,
  settled work is not resent and late results cannot overwrite
  login-in-progress health.
- Restart, shutdown and service signals synchronously gate all new HTTP and
  background-recovery work, cancel Typst children and other managed operations,
  await admitted handlers and conversations, then flush acknowledged checkpoint
  batches and drain provider-health work. Process handoff is refused while a
  provider child remains unclosed.

## Activation and release safety

- Confirmed five-file onboarding activation now records a bounded prepared
  intent before replacement. Startup reconciles already-written targets,
  completes terminal cleanup windows, preserves the intent and user bytes on
  conflicting drift, and completes only unambiguous pending targets. Proposal
  staging, discard and activated-CV repair use the same cross-process workspace
  authority. Failed terminal activation removes only its own marker before
  rollback, and setup readiness validates every activated file against the
  marker hashes.
- Public-source and application staging open allowlisted inputs as verified
  regular files without following symlinks in either the leaf or an ancestor
  component. The release privacy audit applies the same ancestor and opened-file
  identity checks instead of silently following or skipping links. Directory
  enumeration is identity-bound, platform compiler inputs are copied through
  the verified reader, and the complete platform payload is privacy-audited
  before installer, DMG, DEB or archive creation.

## Scout character

  behaviour, including sprite sheets with a partial final row.
- Moving and representative still frames remain centred at dashboard and
  setup sizes, with stable reduced-motion and module-loading fallbacks.

- Usage summaries and model choices now update independently, so a slower response cannot erase information that is already visible.

- When live enumeration is unavailable, Scout labels its short built-in list as fallback suggestions whose current availability is unknown.
- Saved models missing from a refreshed catalogue and models rejected by the provider remain explained but cannot silently masquerade as usable defaults.
- **Other…** remains available for an explicitly entered safe model ID.

## Security, privacy and compatibility

- Provider catalogue and platform checks use fixed arguments, no shell interpolation, bounded execution time and bounded output.
- Raw provider output, registry values, executable paths, account details and operating-system errors are not returned to the browser.
- Provider health and login records contain only bounded state, reason and
  timing fields; one-time codes and raw provider output stay ephemeral.
- No manual workspace-data conversion is normally needed; profile, tracker,
  report, application and backup data remain in place.
- Stop every older Scout process before the first scan starts under Beta 23's
  fenced lease. Do not run old and new Scout binaries against one workspace.
- Current Scout rejects a legacy lock after fenced activation. Older binaries
  do not understand that lease and may still write, so stop every old process
  and disable its schedules; the check does not make coexistence safe.
- Ranked-profile migration creates and verifies a beta.22-compatible workspace
  snapshot before changing profile state. A reviewed rollback materialises the
  snapshot into a separate workspace and never overwrites newer history.
- Publishing the migrated profile re-ranks reconstructible historical
  vacancies into a separate immutable artifact. Existing decisions remain
  unchanged, and profile or scoring provenance that cannot be reconstructed is
  explicitly labelled legacy.

## Clearer scan status and compatibility guidance

- Established workspaces still using earlier search settings show a persistent
  explanation and a direct route to review and publish the search profile.
  Fresh-workspace publication requirements remain in place.
- Scan progress wraps across intermediate phone widths, announces changes and
  retains the complete status text for inspection.
- A delayed opportunities refresh cannot replace a more recent tracker view.
- Repeated assessed keeper content can count as unchanged while verification
  dates and ranking history advance. Changed job content still counts as updated.
- Scheduled queue views no longer label historical compatibility purposes as

- Commute settings explicitly describe assessment context and dashboard

- Existing snapshot escape fixtures now use Windows junctions on Windows.

- Scan and upgrade guides describe current fenced execution, the limits of
  old/new coexistence checks and the bounded semantic facts actually retained.

## Release integrity

- Tagged releases now retain SHA-256 checksums and publish a GitHub/Sigstore keyless attestation bundle covering every package digest. The workflow verifies every subject before publication.
- Every reusable action in any workflow receiving secrets, including CI,
  release builds, attestation and private deployment, is pinned to a reviewed
  immutable full commit SHA. Workflow-policy tests check all such workflows.
- Application and public-source staging omit nested `node_modules` trees;
  lockfile-selected production dependencies still use the dedicated top-level
  staging pass and remain subject to the privacy audit.
- Windows and macOS packages remain operating-system unsigned; the attestation proves release-workflow provenance but does not provide an Authenticode or Apple Developer ID publisher identity.
- The [verification and signing guide](../SUPPLY_CHAIN_SECURITY.md) documents online and offline verification, trust-root rotation, compromised-release handling and the remaining credential-dependent platform-signing work.

## Standalone CV and feedback workflows

- Living CV reads one external Markdown or JSON source, shows an exact approval-bound diff, preserves immutable CV versions and offers profile rebuilding from approved evidence. Scans retain the existing bounded historical reassessment rule.
- Cover letters remain editable drafts and now export DRAFT-labelled PDFs through the bundled Typst path; source edits block stale PDF downloads.
- Local models can create reviewed CV and letter drafts without file tools: they select supplied evidence IDs, Scout copies confirmed passages, and edited previews are saved only after explicit review. CV, source, job and existing-draft revisions are checked again before saving. Guided CV PDFs keep a separate DRAFT path.
- Job feedback has plain forms and thumbs controls, with optional reviewable title/employer ranking proposals. Learned ranking can be reset and the reset undone without deleting history. Employers have private notes alongside existing watch priority, monitoring and health controls.
- Fresh setup proposes browser language, currency and time zone and asks for the optional source country instead of silently choosing the UK. A short Getting started guide and phone-width browser coverage accompany these flows.

## Acceptance still required before publication

The code, browser, migration, rollback, release-stage and privacy suites may
pass on a candidate without proving the maintained private deployment. Live
VPS migration, deployment, rollback and owner acceptance are pending and are
not yet recorded for this candidate. They require the authorised operator and
protected release workflow; no local or pull-request test substitutes for
that evidence.

### Native and browser acceptance

- Windows CI compiles the production tray host and executes C# notification receipt assertions. Delivery state is shared with the real shown-event and HTTP-receipt handlers; failed receipts retry without another balloon, and bounded memory preserves recent identities.
- The Windows runner measures the actual staged payload's longest default installation path and round-trips a staged file above the legacy MAX_PATH boundary.
- CI covers Chromium, Firefox and WebKit on all supported host runners. API-route fixtures block service workers; dedicated worker lifecycle tests explicitly enable them.
- Explicit modal triggers retain keyboard focus on Safari. A failed queued backup resolution returns its error without leaving an unobserved internal promise that can terminate Scout.

### Owner-signed release manifests

- Update downloads now require a trusted Ed25519 detached signature binding the exact version, filename, byte length and SHA-256 before installer transfer. The existing streamed checksum and atomic-write controls remain active.
- An offline installer preflight uses the same verifier. Owner public-key enrollment is required; production downloads fail closed while the bundled registry is empty. CI uses temporary generated test keys only.
- Owner key creation, protected signing, rotation, revocation and manual recovery are documented. Release-candidate tags containing `-rc` do not deploy or publish. F-1 packaging acceptance remains a separate gate.

### First-scan operational choices

- Publishing reviewed search rules, choosing background/active mode, changing schedules and finishing setup retain the existing approved onboarding evidence. The approval marker is not rewritten by these settings saves.
- Changes to evidence, provider/model/endpoint, profile, search preferences, scoring or other reviewed configuration still invalidate first-scan approval. Interrupted activation retains the existing complete-file recovery checks.
